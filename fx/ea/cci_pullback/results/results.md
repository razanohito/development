# CCI 押し目買い (風林火山) EA 検証結果

* 金 (XAUUSD): 1分足 2026-03-26〜2026-09-25 (getdata-finance 無料サンプル) を 5分/15分/1時間/4時間足に変換。前半 = 〜2026-07-06 (下落局面), 後半 = 2026-07-06〜 (上昇・反落局面)
* EURUSD / GBPUSD: 15分足・1時間足 2012-11〜2022-03 (ejtraderLabs)。前半 = 〜2017年, 後半 = 2018年〜
* ロット 0.01 固定・買いのみ・同時に1ポジション。元手 500万円, USDJPY 150 固定
* コスト: 金 スプレッド $0.30・買いスワップ -$50/lot/日、EURUSD 0.5pips・GBPUSD 0.7pips・買いスワップ -$5/lot/日
* シグナルは確定足で判定し、次の足の始値で売買 (未来の足は見ない)。緊急損切の逆指値だけ足の途中で約定

## 結論

* **画像のルールで勝てたのは「金・15分足エントリー・1時間足で環境認識」だけ。** 約6か月で 54 回、勝率 41%、PF 2.12、損益 +31,070円 (0.01ロット)、最大DD 6,579円。前半・後半とも黒字 (前半 PF 1.21 / 後半 PF 4.64)。
* 同じ環境 (上位足が上昇トレンド・CCI≥50) の中でランダムにエントリーして同じ決済ルールを使うと、300回中この成績以上は 1% だけ。CCI のトリガーにはある程度の意味がありそう。ただし取引回数が少なく、金が上昇基調だった半年分しかデータがない。
* 5分足エントリーや4時間足の環境認識に変えると損益はほぼトントンか赤字になり、時間足の選び方に敏感。
* **EURUSD・GBPUSD (約9年) では、どの設定でもほぼ赤字。** 画像のルールそのままだと PF 0.74〜0.90 で、コストを0にしても PF 1 を下回った (このルール自体に優位性がない)。
* **利確「勢いがなくなりレンジになりそうな時」は、早く逃げる定義ほど成績が悪かった。** CCI のピークアウトや +100 割れで降りると利益が伸びず、「高値更新したのに CCI が前のピークを超えない (ダイバージェンス)、または CCI が 0 割れ」で降りる定義が総合1位。EA の既定値はこれにした。
* 0.01 ロットだと元手 500万円に対して損益は ±数万円 (±1%未満) の規模。

## ルールの数値化

| 画像のルール | EA・検証での定義 |
|---|---|
| ① 上位足で上昇トレンド (高値更新・押し安値維持) | 上位足の確定足で、直近2つのスイング高値・スイング安値 (左右2本のフラクタル) がどちらも切り上がり、終値が直近の押し安値より上 |
| ① 上位足 CCI が +100 付近で推移 | 上位足 CCI(14) ≥ 50 (0 / 100 / 条件なし も比較) |
| ② 下位足で CCI が -100〜-150 まで下落後、-100 を上抜け | 下位足 CCI(14) が前の足で -100 以下、確定足で -100 超え。深さの上限 (-200) は任意 |
| ② 陽線包み足 or 下ヒゲ反発 (任意) | 確定足か1本前が陽線包み足、または下ヒゲが足の長さの50%以上 |
| ② 20EMA 付近からの反転 (任意) | 直近10本の安値が 20EMA + 0.5ATR 以下まで来ていた |
| 補足 フィボ 50〜61.8% (任意) | 直近10本の安値が、上位足の直近押し安値→高値の 38.2〜78.6% 押し |
| ③ 損切: CCI 再び -100 割れ + 陰線確定 | 確定足で CCI < -100 かつ 終値 < 始値 → 次の足の始値で決済 |
| (画像になし) 緊急損切 | 直近10本の安値 - 0.2ATR に逆指値 (急落対策。なしも比較) |
| ③ 利確: CCI +100 以上に達した後、勢いが鈍る / ダイバージェンス | 下表の9通りを比較 |
| 補足 CCI 角度で保有期間を調整 | 利確方法「角度で切替」として比較 |

## 注意

* 金のデータは約6か月分 (取引約50回) しかなく、推奨設定は複数の候補から選んでいる。偶然の可能性は残るので、**MT5 ストラテジーテスターで数年分の金データを使った検証と、デモ口座でのフォワードテストを必ず行うこと。**
* MQL5 の EA はこの環境でコンパイル・実行できないため未検証。ロジックは Python 版と同じになるように書いた。
* 金の後半 (7〜9月) は上昇相場で、買いのみのこの手法には追い風だった。前半 (下落局面) の PF は 1.2 程度。
* 1分足から作った足で検証しているため、ブローカーの足 (サーバー時間) とは区切りが少しずれる。
* スワップは日付をまたいだ日数 × 1日分で計算 (水曜3倍は無視)。
